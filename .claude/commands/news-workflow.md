# 뉴스 수집기 새 기능 개발 워크플로

입력받은 브랜치 이름: `$ARGUMENTS`

아래 과정을 순서대로 실행한다. 앞 단계가 끝나기 전에는 다음 단계로 넘어가지 않는다.

## 1. 현재 상태 확인

1. `git status`와 `git branch --show-current`로 현재 브랜치와 커밋하지 않은 변경사항을 확인하고, 결과를 짧게 알려준다.
2. 커밋하지 않은 변경사항이 있으면 알려주고 어떻게 처리할지 확인한다. 임의로 커밋하거나 stash하거나 버리지 않는다.
3. 현재 브랜치가 `main`이면 2단계로 넘어간다.
4. `main`이 아니면 현재 브랜치 이름을 알려주며 경고하고, `main`으로 이동할지 물어본다. 답을 받기 전에는 브랜치를 바꾸지 않는다.
   - 이동에 동의하면 `git switch main`을 실행한다.
   - 거절하면 여기서 중단하고 그 이유를 알려준다.

## 2. 새 브랜치 만들기

1. 위의 "입력받은 브랜치 이름"이 있으면 그 이름을 사용한다.
2. 비어 있으면 어떤 기능을 개발할 것인지 물어보고 답을 기다린다. 답을 바탕으로 영어 소문자-하이픈 형식의 브랜치 이름(예: `article-search`)을 제안하고, 확인을 받은 뒤 사용한다.
3. 이름을 브랜치 이름으로 쓸 수 없거나 같은 이름의 브랜치가 이미 있으면, 알려주고 다른 이름을 확인한다. 기존 브랜치를 덮어쓰거나 삭제하지 않는다.
4. `git switch -c <브랜치 이름>`으로 브랜치를 만들고, 현재 브랜치가 새 브랜치인지 확인한다.

## 3. 개발 시작 안내

1. 브랜치를 만들었으면 '이제 개발을 시작하세요!'라고 안내한다.
2. `CLAUDE.md`와 거기서 참조하는 `AGENTS.md`를 읽고, 이 프로젝트의 기술 스택과 컨벤션을 요약해 다시 알려준다. 이 명령 파일에 적힌 내용이나 기억이 아니라 현재 파일 내용을 기준으로 한다.
3. 개발이 끝나면 '완료' 또는 'DONE'을 입력하라고 알려준다.
4. '완료' 또는 'DONE'(대소문자 무관)을 입력받기 전에는 4단계를 실행하지 않는다. 그 사이의 개발 요청은 평소처럼 처리하되, 임의로 커밋하거나 병합하지 않는다.

## 4. 커밋과 병합

사용자가 '완료' 또는 'DONE'을 입력하면 실행한다.

1. 현재 브랜치가 2단계에서 만든 브랜치인지 확인한다. 다르면 알려주고 어떻게 할지 확인한다.
2. `git status`와 diff를 확인하고, 변경된 파일 목록(추가·수정·삭제 구분, 추적되지 않는 새 파일 포함)을 보여준다. 이미 이 브랜치에 커밋한 변경이 있으면 `git diff --name-status main...HEAD`의 결과도 함께 보여준다.
3. `.env.local`처럼 비밀값이 들어 있을 수 있는 파일은 커밋 대상에서 제외하고 알려준다.
4. 실제 변경 내용과 기존 커밋 로그의 스타일을 바탕으로 커밋 메시지를 제안한다.
5. 커밋 메시지를 보여주며 이 내용으로 커밋하고 `main`에 병합할지 확인한다. 확인을 받기 전에는 커밋하지 않는다. 수정 요청이 있으면 반영한 뒤 다시 확인한다.
6. 확인을 받으면 커밋한 뒤 `git switch main`과 `git merge <브랜치 이름>`을 실행한다. 새로 커밋할 변경이 없고 브랜치에 이미 커밋한 변경만 있으면, 병합할지만 확인한다. 둘 다 없으면 병합할 내용이 없다고 알리고 중단한다.
7. 커밋이나 병합이 실패하거나 충돌이 나면 다음 단계로 넘어가지 말고, 상태를 알려준 뒤 어떻게 처리할지 확인한다. 강제 옵션을 사용하지 않는다.
8. 원격 저장소로의 push와 브랜치 삭제는 하지 않는다.

## 5. 작업 요약

병합이 성공한 것을 확인한 뒤, 다음 내용을 요약해서 보여준다.

- 병합한 브랜치 이름
- 커밋 해시와 커밋 메시지
- 변경된 파일 목록
- 구현하거나 수정한 내용
- 확인한 것과 아직 확인하지 않은 것(실행하지 않은 검증을 한 것처럼 쓰지 않는다)
